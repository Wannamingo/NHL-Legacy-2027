# NHL Legacy для Android / RG477M

Рабочая ветка нативного порта Xbox 360 NHL Legacy. Код PowerPC заранее
рекомпилируется в C++, затем собирается NDK в ARM64. Используется Android-ветка
ReXGlue, SDL для окна, физического контроллера и звука и Vulkan для графики.

Это разработка. Сборка библиотеки и отдельные проверки устройства сами по себе
не подтверждают наличие работающего игрового процесса. Актуальные результаты
находятся в `../ANDROID_PROGRESS.md`.

## Источники

- Игра и декларации функций: [puckhead73/nhl-legacy-recomp](https://github.com/puckhead73/nhl-legacy-recomp).
- Генератор: [rexglue/rexglue-sdk](https://github.com/rexglue/rexglue-sdk),
  `bd9b51918faa71f962fa38af6d5f744af9aba2ce` и исправление bcctr из проекта NHL.
- Android runtime: [Buku313/rexglue-skate3-android](https://github.com/Buku313/rexglue-skate3-android),
  `edd4344723ecac3ffa18c5dcd2fcc268f468ff9e`. Нужные исправления NHL Vulkan
  объединены с его Android-изменениями в `patches/rexglue-nhl-vulkan-android.patch`.
- Проект DOAXBV пользователя: существующие NDK, Java, Android SDK, adb;
  опыт с управлением, упаковкой APK, режимом 60 Гц и изоляцией игрового процесса.
  Его графический движок Xbox 1 не совместим напрямую с GPU Xbox 360.

Патч `rexglue-rg477m-core.patch` разрешает memfd через динамический поиск символа
для совместимости с Android API 28 и сохраняет FPCR/FPSR при переключении fiber.
Все сторонние лицензии остаются в соответствующих исходных деревьях. Данные
игры, сгенерированный код, ключ тестовой подписи и журналы не включаются в Git.

## Сборка на этой машине

Существующий набор инструментов DOAXBV используется без изменения. Другой путь
можно задать переменной `NHL_ANDROID_TOOLS` или параметром `--tools`.

```powershell
python tools/prepare_game.py --game "D:/Games/NHL Legacy/game"
python tools/prepare_android_sdk.py
python tools/build_android.py --host-codegen
python tools/generate_android.py
python tools/prepare_android_sdk.py --verify-only
python tools/build_android.py --sdk
python tools/build_android.py --game
python tools/package_apk.py
python tools/stage_game.py --install
```

Команды выполняются из корня `nhllegacy-android`, нужен настоящий Python 3.11+.
Для Windows-генератора требуется локальный MSVC/Windows SDK и официальный
Windows SDK ReXGlue 0.8.0, распакованный в `private/host-sdk/release-0.8.0/win-amd64`.
Использованный ZIP проверен по SHA-256:
`2031374a8c8ee45e3d61c883a2dd62bf945c703f806acc677953aeb382f9b6f7`.
Генератор компилируется из закреплённых исходников NHL; только его host-runtime
берётся из релиза. Android runtime собирается из исходников отдельной ветки.

`prepare_game.py` проверяет `default.xex` по SHA-256 и создаёт отдельный приватный
manifest. Исходный manifest и оригинальные файлы игры сохраняются.
`stage_game.py` копирует диск в приватное хранилище `org.nhllegacy.port` на RG477M, исключает
Xbox firmware и по умолчанию извлечённые `_compiled`/`_loose_tex`. Для переноса
пользовательских извлечённых ресурсов предусмотрен `--loose`. APK устанавливается
до копирования; файлы пишутся от UID приложения через `run-as`. Копирование
использует двоичный ADB sync, затем проверяются размер каждого файла и SHA-256 XEX.

APK создаётся только при наличии двух настоящих ARM64 ELF-библиотек: игрового
кода `libmain.so` и `librexruntime.so`. Подпись и выравнивание проверяются,
SHA-256 сохраняется в `private/apk/receipt.json`. Файлы игры в APK не входят.
Для переустановки используется отдельный package `org.nhllegacy.port`.

`patches/rexglue-android-cache-read-position.patch` устанавливает позицию чтения
в начало xpso/xsh: Android Bionic открывает a+b в конце файла. Без этого
сохранённый кэш графики сбрасывался при каждом запуске.
`patches/rexglue-vulkan-driver-cache.patch` сохраняет также готовые данные
драйвера Vulkan, проверяя размер, контрольную сумму и совместимость GPU/драйвера.
Шейдеры находятся в папке игры `game/_android_cache/shaders`: описания в
`shareable`, данные драйвера в `device`. Старый кэш шейдеров переносится сюда
при первом запуске. Известные конвейеры готовятся до первого кадра, экран
«Подготовка графики» показывает прогресс. На RG477M подготовка 351 конвейера
заняла 20,08 с без данных драйвера и 0,87–0,95 с при повторных запусках.
Ещё не встречавшиеся варианты добавляются в кэш во время игры; эта функция
не гарантирует подготовку всех возможных сцен и устранение всех фризов.
`native/asset_float_reader.cpp` сохраняет точные данные при чтении little-endian
float загрузчиком арены: scalar FTZ выключен только внутри retail reader
8368E758, затем восстановлен. Это предотвращает потерю координат +/-32 до
смены порядка байтов. Отдельные нативные тесты: `nhl_cache_stream_test`,
`nhl_asset_float_test`, `nhl_half_decode_test`, `nhl_vertex_upload_test`.

## Проверки устройства

Перед запуском в меню приложения выбирается **Исходные пропорции**, **4:3**
или **16:9**. Выбор сохраняется между запусками. Режим «Исходные пропорции»
вписывает изображение без растяжения, используя ширину и высоту кадра игры;
свободная область экрана заполняется чёрным. Он выбран по умолчанию для новых
установок; ранее сохранённый выбор 4:3 или 16:9 сохраняется при обновлении.
Гостевой видеорежим — 960×720 для 4:3 и 1280×720 для 16:9 и исходного режима.
В режиме 4:3 картинка может растягиваться относительно исходного кадра игры.
Счётчик FPS включён по умолчанию в правом верхнем углу. Он считает
кадры, переданные игрой в presenter, со средним значением за последнюю секунду;
это не частота обновления физического экрана.

Патч `patches/rexglue-display-overlay.patch` исправляет флаг широкоформатного
видеорежима при точном соотношении 4:3 и оставляет в Android-счётчике только FPS.

Режим чтения промежуточных текстур по умолчанию — `fast`: на RG477M в обычной
сцене матча наблюдалось около 21–23 FPS вместо 17–18 с `full`. При смене сцен
просадки остаются. Лишние зрители в центре исправлены точным float reader;
исправление подтверждено изображением и пользователем.
Счётчик больше не показывает ложные тысячи FPS после длительного фриза.
`patches/rexglue-original-aspect.patch` позволяет presenter сохранять пропорции
исходного изображения вместо принудительного соотношения сторон дисплея.
`patches/rexglue-gamepad-deduplicate.patch` не допускает повторной регистрации
одного SDL-устройства после начального опроса и события подключения. Без него
встроенный контроллер занимал сразу два Xbox-слота на экране выбора команд.

`nhl_device_probe` опрашивает Vulkan непосредственно на устройстве.
`nhl_fiber_test` проверяет 20 000 возобновлений fiber с разными режимами
округления, флагами FP-исключений и контрольной переменной на каждом стеке.

На RG477M обнаружен Mali-G615 MC6 / Vulkan 1.3.247. Fragment shader interlock
отсутствует, поэтому PC-путь FSI здесь не работает. Включён путь host render
targets. На реальном RG477M запущены титульный экран и вводный матч: лёд,
игроки, счёт и игровые часы отображаются. Повреждённая картинка видеокуба
остаётся отдельной проблемой. Поддержку Adreno следует проверять отдельно.
VP6-мост ПК вызывает Windows ffmpeg.exe и в начальную Android-сборку не входит.

## Режимы качества (проверка на устройстве)

Частота выдачи кадров ограничена 60 FPS для всей игры, включая меню и заставки.
Ограничитель действует на производителя кадров, независимо от счётчика и вертикальной синхронизации.
Патч: `patches/rexglue-frame-limit.patch`. На RG477M в меню получено 59,51 FPS за 10 секунд,
минимальный измеренный интервал 16,737 мс; кадров быстрее 1/60 секунды нет.
Результаты: `private/device-validation-frame-limit.json`, `private/probes/benchmarks/cap-language-720p.json`.
Это верхний предел; достижение стабильных 50 FPS в матче ещё не подтверждено.

В меню добавлены 720p (1280×720), 540p (960×540) и 360p (640×360).
В текущей сборке 540p и 360p временно недоступны: проверка на RG477M подтвердила
повреждённую графику. Сохранённый низкий режим автоматически возвращается на 720p.
Тени: исходные, сглаженные (билинейная фильтрация), мягкие (два прохода размытия).
По умолчанию сохраняется 720p с исходными тенями. Изменения требуют нового запуска игры.
Настройка «Зрители» включает или отключает два игровых прохода зрителей;
выбор сохраняется, по умолчанию зрители включены. Игроки, лёд и борта
сохраняют обычную отрисовку. OFF пропускает целиком подготовку и отправку
проходов 8368FDE0/83691160; обычная симуляция зрителей на CPU остаётся.
Первый вариант, выключавший только draw calls, пользователь проверил:
заметный прирост FPS не подтверждён. Полное отключение проверено в матче:
690 кадров за 29,97 с, средние 23,02 FPS, худший 1% — 7,56 FPS,
максимальный интервал 164,02 мс (без подробной GPU диагностики).
Парного сравнения одной сцены с ON нет; прирост не подтверждён,
стабильные 50 FPS не достигнуты. Запись замера после проверки выключена.

Размер игровых буферов и параметров сцены задаётся hooks из `renderer_hooks.toml`
и `native/renderer_hooks.cpp`. Видеорежим дисплея остаётся HD: переключение гостя
на SD меняет путь рендера. Режимы 540p и 360p остаются экспериментальными:
корректность матча не подтверждена, в предыдущих тестах 360p изображение разрушалось.
Такие замеры не считаются результатом производительности.
Встроенная запись `nhl_benchmark_frames` по умолчанию выключена и сохраняет интервалы
именно игровых кадров в приватный CSV. `tools/device_benchmark.py` считает средний FPS,
95/99-й процентиль времени кадра и число задержек более 100/250 мс.

Патч `patches/rexglue-page-validity-refresh.patch` устраняет потерю обновлений
CPU страниц графической памяти при смене кадров. Отдельный тест
`nhl_shared_memory_test` проходит на RG477M, прежний runtime тест не проходил.
Зелёные блоки полноэкранных VP6 роликов остаются отдельным незавершённым дефектом:
ПК обход через ffmpeg.exe пока не перенесён на Android.
